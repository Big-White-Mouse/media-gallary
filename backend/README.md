# 后端资源服务

独立的 Node.js HTTP 服务，不托管前端，不依赖 Vue 或 Vite。需要 Node.js 22.12 或更高版本，以下命令均在 `backend/` 中执行。

```powershell
npm ci
npm start -- --dir "D:\Pictures"
```

安装依赖后，也可直接运行 `node server.js --dir "D:\Pictures"`。缩略图使用 sharp 的原生异步处理，默认一次生成一张，不在启动或目录浏览时批量转码。

## 开发和配置

```powershell
npm run dev -- --dir "D:\Pictures" --port 9000
```

`dev` 使用 Node 的文件监听功能自动重启服务。默认端口 8080，监听 `0.0.0.0`。目录参数支持 `--dir`/`-d` 或位置参数；端口支持 `--port`/`-p`。环境变量 `GALLERY_DIR`、`PORT` 提供默认值。未指定目录时使用当前工作目录，即通常为 `backend/`。

## 接口

- `GET /api/browse?path=相册`：获取目录下的 `folders`、`images`、`videos`，以及 `directory`、`currentPath`。路径相对于指定媒体根目录。
- `GET /image/<编码后的相对路径>`：获取图片。
- `GET /video/<编码后的相对路径>`：获取视频。
- 资源支持 HEAD 与单段字节 Range；无效范围返回 416。
- `GET /thumbnail/<编码后的相对路径>`：返回原图旁的单份 WebP 缩略图；首次请求进入有界生成队列，未就绪返回 202。规格为长边 768px，不放大小图，不额外生成预览图。
- 原图与缩略图支持 ETag；目录列表提供源版本 URL。目录快照最多缓存 1.5 秒，`/api/browse?refresh=1&path=...` 强制刷新。

## 缩略图存放和释放空间

每个原图父目录的 `.gallery-thumbnails/` 保存该目录的缩略图、清单和短期事务文件。源更新时替换固定文件，不累积多个尺寸或历史版本。该目录不会出现在画廊，也不能从媒体接口访问。

根目录的 `.gallery-thumbnails/catalog.json` 登记本服务已经生成的缓存位置。默认总预算为 2 GiB，包含已登记目录中的文件；可在前端「缓存管理」调整。容量检查为生成事务预留空间，按近期使用回收。清空缩略图后少量清单文件仍会保留，占用不一定严格为零。

「缓存管理」支持查看实际位置与用量、清理当前目录及子树、清空全部已登记缩略图、清理失效项、暂停/恢复生成，以及扫描接管移动或复制进来的受管缓存。首次启动不会扫描整个媒体树。

清空会暂停生成并使旧任务失效，避免后台立即重建；点击「恢复生成」才会再次按需生成。暂停后已有有效缓存仍可读取。原图始终不改动。目录只读、同名目录非本项目所有、编码不支持或磁盘不足时，不会改用其他隐藏路径写入，列表显示占位，点开仍能读取原图。

可停止服务后手动删除这些专用缓存子目录释放空间，重新启动时按需恢复。外部移动目录、损坏/丢失登记时，请使用「扫描并登记已有缓存」核对覆盖范围。只统计当前媒体根内已登记的缓存，不承诺统计未接入的磁盘。

管理接口为 `GET /api/cache` 和 `POST /api/cache`。POST 必须携带 `X-Gallery-Manage: 1` 与 JSON 请求体：`action` 为 `clear`、`prune`、`scan`、`pause`、`resume` 或 `limit`；`scope` 为可选相对目录，`maxBytes` 用于 limit。返回实际释放字节和失败项。不会删除原图或非受管文件。同一媒体根请只运行一个后端写入实例。

BMP/ICO 等浏览器可读但 sharp 不支持的输入仍可直接查看原图；缩略图显示可重试的失败状态。动图缩略图是静帧，查看器加载原始动图。单图生成像素上限为一亿像素。

资源路径使用 `/` 分隔，响应中的媒体 URL 可直接使用。目录边界检查包括符号链接的实际路径。访问后端根路径 `/` 返回 404，网页由独立前端提供。

图片支持 JPG、JPEG、PNG、GIF、WebP、AVIF、SVG、BMP、ICO；视频支持 MP4、M4V、WebM、OGV、OGG、MOV、MKV。具体编码能否播放取决于浏览器。

该服务用于可信局域网，无登录功能。其他设备需处于同一局域网，允许 Node.js 通过防火墙的专用网络。
